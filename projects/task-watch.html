A wearable that checks whether I actually did what I said I would. It uses GPS to confirm I'm where the task happens, and if I skip it, it shocks me.

The problem

My first semester of college, I spent most of my time in my room and slowly stopped putting myself in social situations. Reminders on my phone were easy to swipe away.

I wanted something I couldn't ignore. So I built a watch that gives me a task, checks that I'm actually in the right place to do it, and makes skipping it uncomfortable.

How I approached it

The watch had to answer two questions on its own: did I start the task, and am I really where I said I'd be. A twist knob handles the first. GPS handles the second.

Build log

  1. Design the behavior as a state machine

    Before wiring anything, I mapped the device's behavior into eight states: idle, picking a task, showing it, waiting to start, counting down, checking location, success, and failure.

    Writing it as a state machine made the firmware predictable. Every input has a defined meaning in each state, and nothing happens by accident.

  2. Keep everything running at once

    The ESP32 has to read the knob, parse GPS, update the display, and run a countdown at the same time. Blocking delays would freeze everything else.

    I used non-blocking timers instead, so the main loop processes input at 100 Hz while tasks count down in the background.

  3. Verify location with a geofence

    The GPS module streams coordinates over serial. I compare each fix to a 15-meter radius around where the task should happen, and tasks are also filtered by where I am.

    Raw GPS wanders, especially indoors, so the check requires a stable fix before it counts.

  4. Wire in the consequence

    I opened up a commercial TENS unit, soldered it to a relay, and let the ESP32 switch it. The shock has three intensity levels, and it gets stronger the longer a task is overdue.

    The relay keeps the stimulation circuit fully isolated from the logic side. The ESP32 only ever controls a switch.

  5. Wear it

    I wore it around campus and tested it in real situations. People constantly asked what it was, which turned out to be part of the point. It started conversations on its own.

What I learned

This was my first full embedded build, and it's what pulled me toward computing hardware. Designing behavior as a state machine before writing code is a habit I've kept on every project since.
